# 3FP 内核审计与改造记录

日期：2026-09-06。本文记录本轮代码审计、实际改动和本机验证范围，不等同于所有设备、
所有媒体格式均已验证，也不承诺在解码速度不足或驱动阻塞时永久零丢帧。

## 架构与改造决策

| 层次 | 当前职责 | 本轮处理 |
| --- | --- | --- |
| VB 会话、控制器与原生 API | 异步命令、状态/快照、选流、外部音轨、窗口绑定 | 保留公开 API/ABI；增加跨状态回归 |
| SharedFileInput / FFmpeg demux | 本地共享文件访问、时间轴原点、包读取 | 保留共享打开与协议限制；区分 EOF 与实际读取失败 |
| PlayerSession 解码与队列 | 单工作线程维护解码器、压缩包/帧队列、Seek、硬解回退 | 统一队列饱和判定，加入启动预缓冲和独立排空状态 |
| WASAPI | PCM 重采样、共享/独占端点、音频主时钟 | 修复暂停/启动时钟，完整排空重采样，修正缓冲移交与 EOF 诊断 |
| D3D11 / DXGI | CPU 上传、硬件表面、缩放、HDR 输出、独立图层呈现 | 延迟视频资源预热、呈现背压、分离 HWND 确认与计数、修复 FP16 回读 |
| HDR / 字幕 / 弹幕 / 歌词 | 色彩策略、定时文字和独立图层 | 保留算法与功能；执行既有数值、文字和投影回归 |
| LakeUI 窗框与阴影 | 原生窗体边界、客户区延迟刷新、分层阴影 | 阴影缩放独立于客户区延迟，纯移动复用已有阴影 |

保留“会话工作线程 + WASAPI 事件线程 + 独立呈现线程”的结构。首帧问题不要求把所有
解码器改成多线程生产者；那会扩大 Seek/切轨/设备重建的所有权边界。本轮采用局部结构调整，
不更换渲染后端、不降低缩放/HDR/字幕质量，也不以永久禁止丢帧掩盖时钟问题。

## 首段丢帧根因

测试文件为用户提供的 `Timeline 1_pnat1.mkv`：1920×1080 HEVC Main 10、
30000/1001 fps、48 kHz 双声道 FLAC，音视频起始时间均为 0，时长约 7307.967 秒。

1. **首帧门控不等于启动就绪。** 原实现首次 DXGI Present 后立即释放音频，视频后续帧
   尚未形成解码余量。首帧后的初始化/调度成本进入已经运行的媒体时间，随后触发迟到丢帧。
2. **暂停时间被加入音频位置。** `SetPaused` 原来无条件根据旧 QPC 样本外推，即使端点
   处于暂停/预填充状态。恢复时可以先跳到缓冲末端，再被真实设备时钟拉回。
3. **异步缓存可覆盖未呈现画面。** 赶帧时多个 Render 提交可能先后覆盖单份 GPU 缓存，
   这些损失不一定出现在迟到丢帧计数里。原先首次呈现和 HWND 更换还混用了同一计数基准。

原代码重新构建后，CPU 和 GPU 各三次测试均复现开头 **3 帧迟到丢弃**，通常另有
**1 帧覆盖合并**和 **1 次音频欠载**。测试从 Play 前开始采样，而不是跳过开头再统计稳态。

## 新的启动契约

- 打开/跳转/恢复时，媒体时钟在预缓冲期间冻结；WASAPI 可以预填充，但不得把这些样本
  当作已经播放，也不得根据暂停期间流逝的墙钟外推。
- 对零起点视频，保留“先看到真实首帧，再允许常规音频解码”的现有门控合同。
- 首帧以后仍先填充有界队列；沿用视频约 150 ms、音频目标 120 ms 和既有队列/内存预算。
  音频按完整解码帧入队，实际缓冲可能高于目标，并非硬性裁成 120 ms。
- 只有队列满足条件、到达 EOF 或触及已定义的包容量边界时才结束预缓冲；不增加固定睡眠。
- 对视频起点晚于音频的媒体，在时钟启动前预热渲染资源，但不提前显示未来画面。
- 正常播放时，上一视频代次未确认 Present，下一帧不覆盖它；工作线程仍能补充音频和解复用。
  原生窗口移动期间保留既有非阻塞呈现策略。

## 其他内核修复

- 主容器 EOF、音频解码排空、外部音轨 EOF 分开处理，避免“视频队列等音频，音频又等视频排空”。
- 外部音轨每次只处理一个压缩包，不在同一调用里长时间扫描整个文件；正偏移由音频队列的
  逻辑静音表示。负偏移仍按媒体时间裁剪前滚样本。
- EOF 时排空 `SwrContext` 的尾部样本；正常 EOF 不再记作缓冲欠载。
- PCM 从应用队列交给端点时保持待播放样本计数连续，防止中间瞬间被观察为零缓冲。
- 确认音轨已排空后将剩余视频尾段交给 QPC 时钟；尾段暂停恢复不再等待已结束音轨补充缓冲。
  等待末帧实际呈现及持续时间，再报告播放结束。
- 分离“当前 HWND 已呈现代次”和“已经计数的媒体代次”，避免重绑窗口重复计数或制造合帧记录。
- FP16 回读按四个 16 位半精度通道转换，替换原来的四个 32 位 float 读取；原读法既误解格式，
  也可能读出有效像素数据之外的内容。HDR 白场实测约 `125/125/124.938/1`，符合该测试输入。
- 保留硬解失败回退 CPU 的路径，新增加的资源预热同样遵守回退规则。

## LakeUI 阴影回归

根因在同级 `LakeUI/D3D11GpuEngine/ShadowWindow.vb`：尺寸移动期间 `moveOnly=True`
直接返回，只改阴影位置，不更新阴影位图尺寸。原生宿主已经放大，而阴影仍保持旧尺寸。

修复后，只有宿主尺寸和圆角都未变化时才走纯移动快路；缩放立即重新提交正确大小的分层位图。
同时跳过宿主内部必定透明的区域，减少阴影距离计算，不关闭播放器或 LakeUI 的客户区刷新优化。
LakeUI 测试在 `WM_EXITSIZEMOVE` 之前检查放大、缩小和移动后的原生阴影边界；不能用被延迟更新的
WinForms `Bounds` 代替原生窗口边界作为断言依据。

该改动属于 **另一个 Git 仓库**，需要与播放器改动一起保留。当前 3FP 引用 LakeUI 的 Debug DLL，
本轮已重新构建该依赖。

## 弹幕裁边、串色与缓存复用专项

本轮通过 `FFF.Player.Tests/Native/TimedTextAtlasTests.cpp` 直接编译生产渲染器并读取 GPU 图层，
不是仅验证宽度公式，也不依赖桌面截图。测试不新增播放器导出接口。

发现并修复：

- 默认弹幕测量固定使用普通字形，而实际命令允许粗体、斜体及字体名称后缀解析；现在默认测量走
  原生同源字体解析，并使用当前样式，保留原有自定义测量器接口。
- 精灵按上游布局框加固定留白分配，无法覆盖真实字形超界；部分尖角描边甚至超过简单的笔宽外扩。
  现在合并 DirectWrite 字形外扩与实际描边几何的 `GetWidenedBounds`，独立保存绘制原点偏移。
- 软阴影原先整张图集回写，超界条目的模糊像素会进入其他条目或将来才分配的区域。
  现在清理新槽位，按条目限制阴影回写，并保留完全透明的采样隔离边，不修改描边形状或阴影风格。
- 滚动中使用“右坐标减左坐标”生成尺寸缓存键，浮点消减导致同一文字不断产生新键。
  现在键与布局均使用独立缩放后的宽高；同批重复精灵去重，淘汰布局时保留待栅格化引用，完成后释放。
- 超过初始图集尺寸、仍在总容量上限内的长文字现在先扩容，不会过早落入无软阴影的直接绘制路径。

像素回归记录：

| 项目 | 修改前 | 修改后 |
| --- | --- | --- |
| 低估框宽的粗斜体英文 / 中英混排 | 分别 10199 / 13842 个像素缺失或不同 | 0 / 0 |
| 组合音标与尖角描边 | 50 个像素不同 | 0 |
| 相邻条目的阴影污染 | 688 个像素不同 | 0，逐字节一致 |
| 80 次小数滚动与非等比画布缩放 | 额外栅格化 3 次 | 0 次 |
| 三轮密集混合软阴影，SDR / FP16 图集隔离边 | 新增专项 | 隔离边所有通道均为零 |
| 彩色表情、下划线/删除线、负偏移硬阴影、12 像素粗描边 | 新增专项 | 通过 |
| 同批重复文字、长精灵扩容、512 项布局淘汰 | 新增专项 | 通过，无待绘制悬空引用 |

普通字形比较允许每通道 1 级的 8-bit 栅格量化差；独立与密集软阴影比较允许 2 级模糊量化差，
透明隔离边及相邻缓存污染比较不允许任何非零残留。未将允许的量化差当作“逐位完全相同”。

Debug / Release 构建及 `tools/测试3FP弹幕.ps1` 通过。百条弹幕联合压力使用用户原片
（1080p、约 30 fps）与生成的 720p/30 HDR 短片：图层约 120.2 / 120.3 fps，视频约 30 fps，
零丢帧、零音频欠载，六秒采样期精灵缓存未命中均为零。测试帧率范围改为跟随生产者实际刷新率，
不再将本机正常的 120 Hz 适配误判为超过旧 60 Hz 上限；计数区间允许起止边界的一次在途呈现差。
外部音轨切换、偏移跳转与恢复通过。原片六组启动仍全部零丢帧/合帧/欠载；分层阴影开启时移动
约 30.2 fps、零丢帧/合帧/欠载。

额外执行的 `--information-overlay-regression` 存在与本轮无关的既有标签断言不一致：
预期“实时延迟 25ms”，实际为“缓冲区 25ms”。相关生成逻辑和该标签断言均未修改，失败日志保留。
本轮未提供实际异常弹幕文件，字形复现使用构造文本，不能替代所有字体和所有用户弹幕的穷举。

## 验证边界与后续风险

- 实片用于启动重复验证和指定功能测试；**没有完整播放两小时影片**，也没有模拟所有磁盘和 GPU 负载。
- GPU 验证代表本机实际选择的后端；其他厂商/驱动、运行中硬件移除、所有 CUDA 格式回退仍需设备矩阵。
- FP16 数字回读和 HDR 算法回归不等于物理 HDR 屏幕亮度/ICC/DWM 校准。
- 超长音视频交错、流元数据损坏、没有可靠时长的异常容器仍需专项样本；现有容量限制不能证明覆盖
  任意格式的全部极端包顺序。特别是音轨极早结束但文件尚不能到达 EOF 的情况，应继续增加样本。
- 本轮没有大范围重写字幕/歌词解析器、动态 HDR 算法或 FFmpeg ABI 适配；其既有功能保留，
  但本轮测试不意味着所有字幕特效、图片循环和色彩规格都已穷举验证。
