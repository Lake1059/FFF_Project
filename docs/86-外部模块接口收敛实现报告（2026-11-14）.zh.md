## 1. 结论

WP1–WP4 已按 `docs/85-外部模块接口收敛改进计划（2026-11-14）.zh.md` 全量落地：

- 宿主死接口、431,296 B 载荷缓冲与 ColorExtension 废弃镜像已删除；

### 2.2 WP2：32 B 旧表兼容、握手放宽、所有权

`尝试装载` 先读 8 B 信封（`size` / `version`），再按 `size` 分派：

| 信封 size | 接受版本 | 读取结构 | 处理 |
|---|---|---|---|
| `8` | v3 | 空信封 | 只接受 v3 |
| `32` | v2 / v3 | `色彩变换能力表32` | `设置显示目标 = IntPtr.Zero`，缺列归零 |
| `>= 40` | v3 | 40 B `色彩变换能力表` | 保留显示目标 |
| 其他 | — | — | 拒绝 |

- v3 调用失败时回退 v2 再试一次；
- 握手不再要求 `分析帧` / `复位` 非零，只要求可解析信封与合格版本；
- `解析色彩变换信封(原始大小, 原始版本, 缓冲)` 作为纯函数被 `尝试装载` 调用，便于 ABI 测试；
- `尝试取音频渲染表` / `尝试取音频直通表` 不再提前置“已交出”，新增 `标记音频表所有权已转移()`、`标记直通表所有权已转移()`，由会话在 `FFF3FP_SetAudioRenderPlug` / `FFF3FP_SetAudioPassthroughApi` 返回成功后调用；
- `Dispose` 只在任一所有权标志为真时跳过 `FreeLibrary`；否则正常卸载；
- `支持注入` 改为先真取一次注入表再回答：导出存在但表坏/版本不符时答 `False`，避免 UI 显示可用、`start` 却失败。

`播放器会话.vb` 渲染插槽成功时标记渲染表所有权；直通成功时标记直通表所有权；直通失败 `Finally` 用 `释放音频上下文` 委托归还 `本地表.释放(本地表.上下文)`。释放顺序为：先 `FFF3FP_SetAudioRenderPlug(句柄, IntPtr.Zero)` 撤渲染表，再撤直通表，再 `Dispose`。

### 2.3 WP3：中性模块信封与 legacy adapter

新增 `FFF.Player\Interop\外部模块接口.vb`：

- 单一入口 `FFF3FP_ExternalModuleGetApi(abiVersion, outApi)`，`abiVersion=1`；
- descriptor 40 B：`size/version/id/displayName/capabilities/requirements/flags`；
- module api 32 B；auth api 40 B；processor status 192 B（比旧 184 B 多 `version` 字段）；processor api 40 B；
- 能力编号：`Authorization=1`、`AudioRender=2`、`AudioPassthrough=3`、`Processor=4`、`ColorAnalysis=5`；
- 音频能力直接返回既有 `音频渲染能力表` / `音频直通能力表`，不复制结构；
- `外部模块实例` 接口包含 `描述符`、音频两表、处理器启动/停止/状态、授权状态/文本/提交解锁、`Dispose`，并 `Inherits IDisposable` 以便测试使用 `Using`；
- `LegacyColorModuleAdapter` 包装旧类；`NeutralExternalModule` 实现新 ABI；
- 环境变量：`FFF3FP_EXTERNAL_MODULE_MODE=auto|legacy|neutral`、`FFF3FP_EXTERNAL_MODULE_FILE`、`FFF3FP_MODULE_DIR`；
- 默认中性文件名 `FFF3FP.ExternalModule.dll`；
- 搜索序：目录覆盖 → `FFF3FP_MODULE_DIR` → 真实 exe 目录\Modules → 真实 exe 目录 → `AppContext.BaseDirectory\Modules` → `AppContext.BaseDirectory`；
- `运行模式()` 未知值回落 `auto`，大小写归一；`探测()` 在 auto 下先试中性、失败回退 legacy；`neutral` 模式不静默回退；
- `显示名称()` 中性 descriptor 优先，旧模块回退 `"可选扩展模块"`；
- `NeutralExternalModule.Dispose` 任一所有权标志为真则不 `FreeLibrary`。

UI 中性化：

- `Form1.vb` 改用 `外部模块接口.探测/提交解锁码/解锁结果/显示名称`；
- 文案：`检测到可选扩展模块「{displayName}」，但尚未解锁。`、标题`扩展模块解锁`、成功`扩展模块已解锁。`；
- 调试前缀 `"色彩变换模块："` → `"扩展模块："`；
- 方法 `启动时探测色彩变换模块` → `启动时探测扩展模块`；
- `Form1` 注释中的 `FFF.HDRdp.Test.dll` 与 `%LOCALAPPDATA%\FFF.HDRdp.Test` 已中性化；
- `播放器会话.vb` 字段改为 `Private 色彩模块实例 As 外部模块实例`，`支持注入`→`处理器可用`、`启动注入`→`启动处理器`、`停止注入`→`停止处理器`；
- `播放器信息图层呈现器.vb` 注释 `EL 残差合成状态` → `扩展合成状态`；
- `Form1.Designer.vb` 图标在 `ICO.ico` 缺席时回退到 exe 内嵌图标的关联图标，单文件包不再需要图标 sidecar。

## 4. 发布与合规边界

- 3FP 本体只发布自身；外部模块是可选外部件，不随本体包；
- 单文件本体包不内嵌 38 个许可文件，不做许可索引页，不做 release `licenses.zip`；许可入口是仓库主页 `https://github.com/Lake1059/FFF_Project`；
- 单文件发布输出中的 `LICENSE.txt`、`LICENSING.md`、`NOTICE`、`THIRD-PARTY-NOTICES.md`、`licenses/`、`ai-subtitles\AI字幕包声明.txt`、`ICO.ico` 已由 `tools\发布3FP单文件.ps1` 清理；AI worker 脚本保留；
- 散装本体包仍按既有许可流程携带 `LICENSE.txt`、`NOTICE`、`LICENSING.md`、`THIRD-PARTY-NOTICES.md`、`ASSETS.md`、`licenses/`；
- FFmpeg 不随 3FP 本体发布；`发布3FP.ps1` 在未显式 `-IncludeExternalRuntime` 时拒绝 `av*.dll`；
- 模块解锁后的注入内容才是侵权相关；本体只保留中性接口和 legacy 适配层；
- 发布护栏保留旧商标匹配键，但拒绝全部外部模块 DLL，提示文案不再推荐任何具体模块文件名。

## 5. 已知限制与未覆盖项

1. `tools\构建3FP.ps1` 的完整 Debug 构建仍受 vcpkg `libiconv:x64-windows` 失败影响（`cl` 收到未知 `-compiler`/`-Xcompiler` 选项，`libicrt_a-error.obj` 等失败）；这不是 VB 代码错误。为通过 Player Debug 构建，当前 `FFF.Native\x64\Debug\FFF.Native.dll` 是 Release 副本，不是正式 Debug 原生产物；正式 Debug 内核构建仍需修 vcpkg 工具链。
2. WP4 的生命周期测试是模块装载/卸载级 100 次，不是真实 `打开→播放→seek→换文件→关闭` 的播放级压力；尚未跑 Application Verifier/PageHeap。
3. 假模块分支 6“无可选能力”仍是同一个 DLL 导出全部符号，通过返回 unsupported 模拟“缺可选能力”，不是物理缺导出。
4. 旧模块没有 descriptor，`displayName` 回退为 `"可选扩展模块"`；如果希望 legacy 件显示更具体名称，需要旧件提供名称入口。
5. 宿主已删除 `原生色彩变换载荷` 431,296 B 镜像，因此 ABI 测试不再对账该托管结构；内核侧 `FFF3FPColorTransformPayload` 仍是模块—内核数据面契约，不属于宿主镜像。
6. 主路径仍有内部命名“色彩变换通路/色彩变换内容描述”等；它们不是具体模块文件名或导出名，未纳入中性扫描失败条件。
7. 散装发布脚本输出警告：`tools\check_ffmpeg_variant.py` 未找到，FFmpeg 变体判定未执行；这是既有工具缺失，不影响本次模块改造，但发布前应补齐。
