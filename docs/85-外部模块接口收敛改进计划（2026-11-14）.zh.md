## 1. 约束与不变量

### 1.1 必须保持的行为

1. **模块缺席是常态**：盘上没有模块、装载失败、旧件、未解锁、表不合格，都必须与“没这功能”同形，不弹错、不改默认行为。
2. **自驱动泵不搬回宿主**：泵线程、游标、回退探测、投表继续在模块内部；宿主只 start/stop/readStatus。
3. **内核表所有权语义**：`FFF3FP_SetAudioRenderPlug` / `FFF3FP_SetAudioPassthroughApi` 在成功返回后复制表并接管 `context`；失败时必须由调用方归还。
4. **撤表先于卸载模块**：任何内核仍持有的裸函数指针，必须在模块 `FreeLibrary` 之前撤掉。
5. **发布护栏匹配键不改名**：`FFF.Player.vbproj` 和发布脚本里的旧商标文件名是 denylist 资产，不得为了“中性化”改掉匹配键；只改提示文案和正常加载路径。
6. **本体包不含模块 DLL**：模块是可选外部件，不随 3FP 本体发布。

### 1.2 已知边界

- 外部模块源码/二进制不在本仓，WP3 的新入口只能在模块侧实现后才能真验证；仓内用假模块验证宿主行为。
- 真实模块的音画回归需要拥有模块的环境；仓内回归只能覆盖宿主、ABI 镜像、假模块和生命周期。
- 当前 PR58 是单文件许可/关于页改动；加入 docs 84/85 是文档扩展，加入 WP1/WP2 是宿主清理；WP3 会显著扩大 PR 范围，必须用提交边界控制。

### 1.3 命名口径

| 旧名 | 新名/中性名 | 说明 |

## 4. WP2：旧表兼容、握手放宽、裸表所有权（P0/P1，不改模块）

### 4.1 目标

1. 让 32 B 旧表按 size 正确读取，不再“归一化后又被 `size < 40` 拒绝”；
2. 握手不再强制宿主不调用的 `分析帧/复位`；
3. 音频表“创建”和“所有权转移”分开，内核拒绝时归还 context；
4. `Dispose` / 会话释放顺序对所有裸表一致。

### 4.2 旧表读取

#### 4.2.1 现状

`尝试装载` 分配 40 B 表，旧模块只写 32 B；尾部 8 B 是宿主零初始化区，**当前不构成越界读**。真正的问题是：

```vb
If 表.大小 < 40 Then 表.设置显示目标 = IntPtr.Zero
...
If ... 表.大小 < 40 ... Then 拒绝
```

归一化没有改变 `表.大小`，所以旧表仍被拒。

#### 4.2.2 改法

新增两个镜像：

```vb
<StructLayout(LayoutKind.Sequential)>
Friend Structure 色彩变换能力表32
    Public 大小 As UInteger
    Public 版本 As UInteger
    Public 变换版本 As IntPtr
    Public 分析帧 As IntPtr
    Public 复位 As IntPtr
End Structure

<StructLayout(LayoutKind.Sequential)>
Friend Structure 色彩变换能力表40
    Public 大小 As UInteger
    Public 版本 As UInteger
    Public 变换版本 As IntPtr
    Public 分析帧 As IntPtr
    Public 复位 As IntPtr
    Public 设置显示目标 As IntPtr
End Structure
```

`尝试取主表` 的流程：

1. 分配 40 B 缓冲并零初始化；
2. 先按版本 3 调 `取表`；
3. 从缓冲首 4 B 读 `size`；
4. `size == 8`：只读信封，接受，不读任何函数指针；
5. `size == 32`：按 `色彩变换能力表32` 读，`设置显示目标` 置零；
6. `size >= 40`：按 `色彩变换能力表40` 读；
7. `size` 在 9–31 之间或版本不符：拒绝，不读结构体；
8. 若版本 3 调用失败，且模块可能是 v2：用版本 2 + 32 B 缓冲重试一次；成功则按 32 B 接受。

> 关键：先读 `size` 再决定结构体，不要先 `PtrToStructure` 40 B 再检查。这样即使未来模块改成“返回自己的 32 B 指针”，也不会越界。

#### 4.2.3 握手条件

旧：

```vb
表.版本 <> 表版本 OrElse 表.大小 < 40 OrElse
表.分析帧 = IntPtr.Zero OrElse 表.复位 = IntPtr.Zero
```

新：

```vb
' size=8：只有信封，允许（新中性模块可以只提供 Processor/音频能力）
' size=32：允许 v2（或 v3 但 size=32 的过渡件）
' size>=40：要求 v3
If 表.大小 = 8 Then
    If 表.版本 <> 表版本 Then 拒绝
ElseIf 表.大小 = 32 Then
    If 表.版本 <> 2UI AndAlso 表.版本 <> 表版本 Then 拒绝
ElseIf 表.大小 >= 40 Then
    If 表.版本 <> 表版本 Then 拒绝
Else
    拒绝
End If
```

`分析帧` / `复位` / `设置显示目标` 不再参与接受/拒绝。保留 `表.分析帧` 字段只为 legacy adapter 兼容；主路径不调用。

### 4.3 音频表所有权

#### 4.3.1 现状

- `尝试取音频渲染表` 在返回前 `_音频表已交出 = True`；
- `尝试取音频直通表` 在返回前 `_直通表已交出 = True`；
- 内核可能拒绝；此时表并未真正交出，但标志已置位；
- `Dispose` 只看 `_音频表已交出`；
- 直通侧内核拒绝时没有调用模块 `destroy`。

#### 4.3.2 改法

1. 把 `_音频表已交出` / `_直通表已交出` 改为：

```vb
Private _音频表所有权已转移 As Boolean
Private _直通表所有权已转移 As Boolean
Private ReadOnly Property 任何裸表所有权已转移 As Boolean
    Get
        Return _音频表所有权已转移 OrElse _直通表所有权已转移
    End Get
End Property
```

2. `尝试取音频渲染表` / `尝试取音频直通表` **不再**置位；只返回表。
3. 新增：

```vb
Friend Sub 标记音频表所有权已转移()
    _音频表所有权已转移 = True
End Sub

Friend Sub 标记直通表所有权已转移()
    _直通表所有权已转移 = True
End Sub
```

4. `安装音频渲染插槽核心`：

```vb
If 结果 = 原生播放器结果.成功 Then
    已交给内核 = True
    音频插槽已装 = True
    色彩模块实例.标记音频表所有权已转移()
Else
    ' 归还 context
    ...
End If
```

5. `安装音频直通插槽核心`：

```vb
If 结果 = 原生播放器结果.成功 Then
    直通插槽已装 = True
    色彩模块实例.标记直通表所有权已转移()
Else
    ' 新增：归还 context
    If 本地表.释放 <> IntPtr.Zero AndAlso 本地表.上下文 <> IntPtr.Zero Then
        Marshal.GetDelegateForFunctionPointer(Of 释放音频上下文)(本地表.释放).Invoke(本地表.上下文)
    End If
End If
```

6. `Dispose` 早退条件：

```vb
If 任何裸表所有权已转移 Then Return
```

7. `播放器会话.释放` 在 `色彩模块实例?.Dispose()` 之前补：

```vb
' 撤渲染表：内核会对模块 context 调 destroy，必须在模块卸载前。
If 句柄 IsNot Nothing Then 播放器原生接口.FFF3FP_SetAudioRenderPlug(句柄, IntPtr.Zero)
```

直通撤表保留现状（已在 `:1287`）。

## 5. WP3：中性模块信封与 legacy adapter（P2，模块需配合）

### 5.1 目标

用一个中性入口替代 5 个 `FFF_Get*` 和 3 个 `FFF_ColorTransform*` 裸导出；旧模块通过 legacy adapter 继续工作；本体主路径不再出现具体模块名/导出名。

### 5.2 新 ABI 草案

```c
#define FFF3FP_EXTERNAL_MODULE_ABI 1u

enum FFF3FPExternalCapability : uint32_t {
    Authorization     = 1,
    AudioRender       = 2,
    AudioPassthrough  = 3,
    Processor         = 4,
    ColorAnalysis     = 5,  // 可选，宿主驱动分析才需要
};

struct FFF3FPExternalModuleDescriptor {
    uint32_t size;
    uint32_t version;
    const char* id;             // 稳定 opaque，例如 "com.example.hdr"
    const char* displayName;    // 宿主可显示；可为空
    uint32_t capabilities;      // 位掩码
    uint32_t requirements;      // 需要内核哪些通用导出
    uint32_t flags;             // requiresActivation / singleton 等
};

struct FFF3FPExternalModuleApi {
    uint32_t size;
    uint32_t version;
    void* context;
    int32_t (*getDescriptor)(void* context, FFF3FPExternalModuleDescriptor* out);
    int32_t (*getCapability)(void* context, uint32_t capability,
                             uint32_t version, void** outTable);
};

extern "C" __declspec(dllexport)
int32_t FFF3FP_ExternalModuleGetApi(uint32_t abiVersion,
                                   FFF3FPExternalModuleApi* out);
```

能力表：

```c
struct FFF3FPExternalAuthApi {
    uint32_t size;
    uint32_t version;
    void* context;
    int32_t (*getState)(void* context);              // 0/1/2
    const char* (*getText)(void* context, uint32_t purpose); // 1/2/3
    int32_t (*submit)(void* context, const char* credentialUtf8); // 0/1/2
};

struct FFF3FPExternalProcessorStatus {
    uint32_t size;
    uint32_t version;
    uint32_t running;
    uint64_t processedFrames;
    uint64_t unchangedFrames;
    uint64_t skippedFrames;
    uint64_t unattributedFrames;
    int64_t  lastFrameIndex;
    float    lastPeakNits;
    char     statusText[64];
    char     detailText[64];
};

struct FFF3FPExternalProcessorApi {
    uint32_t size;
    uint32_t version;
    void* context;
    int32_t (*start)(void* context, FFF3FPHandle session);
    void (*stop)(void* context);
    void (*getStatus)(void* context, FFF3FPExternalProcessorStatus* out);
};
```

`AudioRender` / `AudioPassthrough` 直接返回既有内核结构，不复制。

### 5.3 宿主侧文件

新增：

- `FFF.Player\Interop\外部模块接口.vb`
  - `外部模块描述符` / `外部模块Api` / `外部授权Api` / `外部处理器Api` 镜像；
  - `尝试装载中性模块`；
  - `尝试取能力(capability, version)`；
  - 搜索序：`FFF3FP_MODULE_DIR` → `Modules` → 真实 exe 目录 → `AppContext.BaseDirectory`。
- `FFF.Player\Interop\LegacyColorModuleAdapter.vb`
  - 把现有 `色彩变换模块接口.vb` 的旧常量/旧类机械搬入；
  - 实现统一的 `外部模块实例` 接口；
  - 文件头标注 `DEPRECATED`，只保留一个发布周期。

新增接口：

```vb
Friend Interface 外部模块实例
    ReadOnly Property 描述符 As 外部模块描述符
    Function 尝试取音频渲染表(ByRef 原因 As String) As Nullable(Of 音频渲染能力表)
    Function 尝试取音频直通表(ByRef 原因 As String) As Nullable(Of 音频直通能力表)
    Sub 启动处理器(会话句柄 As IntPtr)
    Sub 停止处理器()
    Function 读取处理器状态(ByRef 状态 As 外部处理器状态) As Boolean
    Function 授权状态() As 外部授权状态
    Function 授权文本(用途 As 外部授权文本用途, Optional 目录覆盖 As String = Nothing) As String
    Function 提交解锁码(码 As String, ByRef 详情 As String) As 外部解锁结果
    Sub Dispose()
End Interface
```

`播放器会话.vb` 改为持有 `外部模块实例`，不再直接持有 `色彩变换模块实例`。为避免一次大改，分两步：

- **WP3a**：引入接口 + legacy adapter 包装旧类，会话改调接口，行为与今天完全一致；
- **WP3b**：新增 `NeutralExternalModule` 实现，`自动` 模式优先新入口，找不到回退 legacy adapter。

### 5.4 选择模式

新增宿主侧环境变量（仅用于测试/回滚，不暴露给普通用户）：

```text
FFF3FP_EXTERNAL_MODULE_MODE = auto | legacy | neutral
```

- `auto`（默认）：先尝试 `FFF3FP_ExternalModuleGetApi`，失败回退 legacy；
- `legacy`：只走旧适配器；
- `neutral`：只走新入口，缺入口即静默降级。

这样 WP3 出问题时可以立即切回 `legacy`，不需要回滚代码。

### 5.5 UI 中性化

`Form1.vb` 三处文案改为 descriptor 驱动：

```text
检测到可选扩展模块「{displayName}」，需要激活。
```

`displayName` 为空时回退“可选扩展模块”。解锁成功文案同理。

`播放器信息图层呈现器.vb` 的源码注释 `EL 残差合成状态` 改为“扩展合成状态”；用户可见文本仍由模块 `detailText` 提供，宿主不解释。

### 5.6 发布护栏

`FFF.Player.vbproj:341` 和发布脚本的旧文件名匹配键**不改**；只把提示文案从“发现特定模块”改为“发现禁止随包发布的私有模块”。护栏仍是 denylist，不是接口。

### 5.7 验收

```powershell

rg -n "FFF\.HDRdp|FC_COLORTRANSFORM_DIR|FFF_ColorTransform|FFF_GetElComposition|FFF_GetInjection" FFF.Player

# 主路径不应出现旧 UI 文案
rg -n "色彩变换模块" FFF.Player\Form1.vb
```

期望：

- 第一条只命中 `LegacyColorModuleAdapter.vb`（WP3b 完成后可为零）；
- 第二条为零，或只剩“外部扩展模块”中性词；
- 新入口假模块可装载；
- 旧模块通过 `legacy` 模式可装载；
- `auto` 模式优先新入口，新入口缺席时回退旧适配器；
- 模块显示名来自 descriptor，不再写死。

### 5.8 风险与回滚

- 风险：高。涉及模块侧实现、宿主抽象层、UI 文案、发布护栏。
- 回滚：`FFF3FP_EXTERNAL_MODULE_MODE=legacy` 立即回到旧路径；代码层 `git revert C3`。
- 不在 WP3 改内核数据面 ABI；音频/直通/辅层/色彩 payload 继续用既有结构。

```text

```

## 10. 明确不做

1. **不复活内核 ColorExtension 四个导出**：它们永久惰性、进程级、无模块参数；复活会破坏 absent 语义。
2. **不把自驱动泵搬回宿主**：当前“模块追帧、宿主只 start/stop”的分工是更安全的隔离形态。
3. **不新增内核数据面 ABI**：音频表、直通表、辅层合成、kind=3 payload、边数据、快照、呈现计数都已够用。
4. **不发布模块 DLL**：模块是可选外部件，本体包只保留中性接口和加载器。
5. **不改发布护栏的旧文件名匹配键**：denylist 是合规资产，不是接口。
6. **不在 WP1/WP2 改模块二进制**：前两个包纯宿主，模块可以完全不动。

**计划结论**：先把宿主从旧 ABI 的“死面”里拔出来，再修 32 B 表与裸表所有权；这两步不需要模块配合，能立刻降低专用面和内存浪费。中性模块信封是第三步，必须带 legacy adapter 和 `auto/legacy/neutral` 回退；最后用 ABI 回归、假模块、生命周期和发布扫描把行为锁住。这样 PR58 既能承载分析与计划，也能按提交边界逐步扩展，不会把“文档审查”和“模块 ABI 迁移”混成一个不可回滚的大提交。
