# 窗口内容 1:1 与自动最大化模式——全量规划与首轮实测

- 日期：2026-11-13
- 状态：已实施；Debug/Release 全解决方案构建通过；三套回归通过；首轮 GUI 物理像素矩阵见 §9.4；100/125/200% DPI 与多显示器仍待补
- 涉及工程：`FFF.Player`（VB/WinForms），复用 `FFF.Native` 既有能力，不改 C++ 渲染器
- 基线：`_wt_pr57` / `fix/pr57-p0-p1-ai-subtitle`，PR #57 修复后的树

## 1. 需求与最终口径

用户原话：“软件默认情况下打开窗口中间用于内容显示的大小=内容大小，做到和显示器像素 1 比 1；如果内容大小=或者大于显示器的情况下，则自动窗口最大化。”

拆成可验收的四条：

1. **内容区 1:1**：视频/图片可见像素区域的设备像素尺寸等于内容源尺寸（旋转后），不乘 DPI、不做缩放。
2. **窗口包住内容**：窗口总尺寸 = 内容区 + 顶部标题栏/底部控制栏 + 窗口外框；内容区之外的黑边不算“内容显示区”。
3. **放不下就最大化**：内容宽或高达到/超过当前显示器工作区，或“内容 + 界面 chrome”已经放不进工作区，窗口进入 `Maximized`。
4. **默认行为**：新模式下每次打开媒体都按上述规则执行；用户手动选过尺寸后，本次媒体不再自动覆盖，下一次打开媒体恢复自动。

### 1.1 已确认边界

用户已确认：**内容宽或高任一达到/超过当前显示器工作区时，直接最大化窗口**，不再要求“最大化时隐藏 chrome 的严格 1:1”。因此本功能只对以下情况承诺严格像素 1:1：

- **内容 < 工作区，且“内容 + chrome”也放得下**：普通窗口，内容区设备像素 = 旋转后的内容尺寸。
- **内容 ≥ 工作区，或“内容 + chrome”放不下**：直接最大化；最大化后内容可能被窗口拟合，**不追加沉浸式无边框/隐藏 chrome 方案**。
- 小内容低于宿主默认 `MinimumSize`（875×500）时，**内容模式按本次目标临时放宽 `MinimumSize`**，让 640×360 这类内容仍得到严格 640×360 的可见内容区；退出模式恢复原最小尺寸。见 §6.5。

## 2. 方案总览

不另造窗口几何，在现有 `播放器窗口布局控制器` 上增加“内容原始尺寸策略”：

```
媒体已打开
  -> 取快照内容尺寸（coded raster）
  -> 按当前视图旋转交换宽高
  -> 若模式关闭 / 纯音频无视频 / 全屏 / 手动覆盖：退出
  -> 恢复 Normal，PerformLayout，量出 chrome
  -> 目标窗口 = 内容 + 客户区非内容 + 非客户区
  -> 判定：内容 >= 工作区 或 目标窗口 >= 工作区 ? Maximized : Normal+居中
  -> 应用：WindowState / Bounds
  -> 原生尺寸封顶 = True（旧内核不支持则跳过）
  -> 主动重绑输出窗口
```

关键选择：

| 决策 | 选择 | 理由 |
|---|---|---|
| 模式开关 | 独立 Boolean，默认关闭 | 不改既有用户行为；不移动 `初始画面尺寸选项` 索引 |
| 1:1 目标 | `画面控件.ClientSize` 设备像素 = 旋转后 coded 宽高 | 与“原始视频”菜单同口径；不引入 DAR 误差 |
| 放不下判定 | 内容≥工作区 **或** 目标窗口≥工作区 | 覆盖“内容略小但 chrome 放不下”的边界 |
| 最大化实现 | `WindowState=Maximized` | 与全屏状态分离；复用现有重绑节流 |
| 防放大 | 新模式期间启用 `SetFitLimitToNative` | 最小窗口/最大化时内容小于视口仍保持 1:1；旧内核可选跳过 |
| 应用次数 | 每次媒体打开一次；模式切换/DPI/旋转重放 | 避免播放中窗口抖动 |
| 手动干预 | 菜单选尺寸后本次媒体暂停自动，下一媒体恢复 | 不跟用户抢窗口 |
| 小内容 | 内容模式临时放宽 `MinimumSize`，退出恢复 | 保证普通窗口内容区严格等于源尺寸 |

## 4. 几何算法

### 4.1 内容尺寸

```vb
Friend Shared Function 计算旋转后内容尺寸(内容 As Size, 四分一转 As UInteger) As Size
    If 内容.Width <= 0 OrElse 内容.Height <= 0 Then Return Size.Empty
    If (四分一转 And 1UI) <> 0UI Then
        Return New Size(内容.Height, 内容.Width)
    End If
    Return 内容
End Function
```

- 内容来自 `e.快照.视频宽度/视频高度`；为 0 时用 `e.媒体信息` 当前视频流兜底；仍为 0（纯音频/光盘菜单）则不改变窗口。
- 旋转来自 `播放控制器.当前视图旋转`；图片 EXIF 旋转同样在该值里。
- 不乘 `DeviceDpi`；1:1 是设备像素。

`Form1.解析内容尺寸` 优先快照，其次媒体信息当前视频流，排除封面图；纯音频/无视频返回空。

### 4.2 目标窗口

```vb
Friend Shared Function 计算内容窗口大小(内容设备大小 As Size,
                                          客户区非内容 As Size,
                                          非客户区 As Size) As Size
    Return New Size(
        Math.Max(1, 内容设备大小.Width + 客户区非内容.Width + 非客户区.Width),
        Math.Max(1, 内容设备大小.Height + 客户区非内容.Height + 非客户区.Height))
End Function
```

量取口径：

- `客户区非内容 = Form.ClientSize - MP_DX视频容器.ClientSize`；
- `非客户区 = Form.Size - Form.ClientSize`；
- 必须在 `WindowState=Normal` + `PerformLayout()` 之后量；最大化状态不能拿来算。

### 4.3 最大化判定

```vb
Friend Enum 内容窗口放置
    普通
    最大化
End Enum

Friend Shared Function 决定内容窗口放置(内容设备大小 As Size,
                                         目标窗口大小 As Size,
                                         工作区 As Rectangle) As 内容窗口放置
    If 内容设备大小.Width >= 工作区.Width OrElse
       内容设备大小.Height >= 工作区.Height Then Return 内容窗口放置.最大化
    If 目标窗口大小.Width >= 工作区.Width OrElse
       目标窗口大小.Height >= 工作区.Height Then Return 内容窗口放置.最大化
    Return 内容窗口放置.普通
End Function
```

- 用 `>=`：内容正好等于工作区时 chrome 必然放不下，等号就最大化。
- 工作区用 `Screen.FromControl(窗体).WorkingArea`，不是 `Bounds`。
- 多显示器以窗口当前所在屏幕为准；启动图片 Attach 前若未显示，`界面已就绪` 后重算。

### 4.4 应用顺序

```vb
Private Sub 应用内容尺寸布局()
    If Not 内容模式启用 OrElse 手动覆盖 OrElse 全屏状态 Then Return
    If 最后内容设备大小.IsEmpty Then Return

    If 窗体.WindowState <> FormWindowState.Normal Then
        窗体.WindowState = FormWindowState.Normal
    End If
    窗体.PerformLayout()

    ' 量客户区非内容 / 非客户区
    Dim 工作区 = Screen.FromControl(窗体).WorkingArea
    Dim 目标 = 计算内容窗口大小(...)
    Dim 放置 = 决定内容窗口放置(...)

    If 放置 = 内容窗口放置.最大化 Then
        窗体.WindowState = FormWindowState.Maximized
    Else
        Dim 最小窗口 = 计算内容模式最小尺寸(默认最小尺寸, 目标)
        If 窗体.MinimumSize <> 最小窗口 Then 窗体.MinimumSize = 最小窗口
        窗体.StartPosition = FormStartPosition.Manual
        窗体.Bounds = 计算工作区居中边界(目标, 工作区)
    End If

    设置封顶(True)
    重绑输出窗口()
End Sub
```

- 只在 `Normal` 下设 `Bounds`；最大化时不要设 `Size`。
- 主动重绑一次，避免最大化后第一帧仍用旧交换链。

### 4.5 小内容与最小窗口（首轮实测后修正）

`Form1.vb` 默认 `MinimumSize = New Size(875, 500)`，但内容模式验收要求普通窗口内容区严格等于内容尺寸；两者在 640×360 上冲突。

原实现：

- 640×360 目标 644×527，被 `MinimumSize` 托到 875×527；
- 视频容器实测 **871×360**，被横向拉宽，不是 640×360。

修正：

- 控制器构造时保存 `默认最小尺寸`；
- 每次应用内容尺寸用 `计算内容模式最小尺寸(默认最小尺寸, 目标窗口)` 取较小值，临时放宽 `Form.MinimumSize`；
- `设置内容尺寸模式(False)` 恢复 875×500；
- 640×360 最终窗口 644×527，`MP_DX视频容器`/画面子窗口均 **640×360**。

```vb
Friend Shared Function 计算内容模式最小尺寸(基础最小尺寸 As Size,
                                             目标窗口大小 As Size) As Size
    If 目标窗口大小.Width <= 0 OrElse 目标窗口大小.Height <= 0 Then Return 基础最小尺寸
    Return New Size(
        Math.Max(1, Math.Min(基础最小尺寸.Width, 目标窗口大小.Width)),
        Math.Max(1, Math.Min(基础最小尺寸.Height, 目标窗口大小.Height)))
End Function
```

放宽只在内容模式且目标需要时发生，不影响默认关闭模式的旧行为。

## 5. 触发与生命周期

| 触发 | 行为 | 备注 |
|---|---|---|
| 媒体已打开（视频/图片） | 取快照尺寸、旋转，应用内容尺寸 | `Form1` 媒体事件末尾调用 |
| 启动时模式已开启 | 不再调用 `应用初始画面尺寸` | 避免先落 854×480 再改 |
| 图片启动（先开图后 Attach） | 先存内容；Attach 后 `界面已就绪` 再应用 | `Form1` 两个 BeginInvoke 后 |
| 设置模式打开 | 当前有媒体立即应用 | `Form1.应用内容尺寸模式设置()` |
| 设置模式关闭 | 停止自动；释放封顶；恢复默认最小尺寸 | 当前窗口不强制缩回 |
| 用户从尺寸菜单选尺寸 | `手动覆盖=True`，本次媒体不再自动；关闭封顶 | `调整画面尺寸` |
| 下一次媒体打开 | `手动覆盖=False`，重新自动 | 每次打开恢复 |
| DPI 改变 | `重新应用内容尺寸()` | 全屏时跳过 |
| 进入全屏 | 挂起；关闭封顶，不改自动状态 | FullScreenChanged |
| 退出全屏 | 模式开且无手动覆盖则重放 | 恢复后应用 |
| 用户手动旋转 | 交换宽高并重算 | `视图旋转控制器` 回调 `更新内容旋转` |
| 视频流切换 | 首版不自动 | 避免播放中窗口抖动 |
| 打开纯音频/空内容 | 清空上次内容；纯音频补默认初始尺寸 | 防止 DPI 变化拿旧尺寸；修复设计器大窗口；关闭媒体不额外清空 |

`FFF3FP_SetFitLimitToNative` 已由静态 `DllImport` 改为动态可选导出：

| 纯音频 WAV | 1281×720（854×480 逻辑 @150%） | 1285×887 | Normal | 修正后通过；修正前停在设计器默认大窗口 |
| 1280×720 + 90° 显示旋转元数据 | 720×1280 | 724×1447 | Normal | 通过（旋转交换宽高） |
| 模式关闭 + 1280×720 视频 | 1281×720（旧预设 854×480 @150%） | 1285×887 | Normal | 旧行为保持 |

**本次实测发现并修正的两个问题**：

1. **小内容被 `MinimumSize` 横向拉宽**：640×360 原实现窗口 875×527、视频容器 871×360；改为内容模式临时放宽最小尺寸后，窗口 644×527、内容区 640×360。新增 2 条纯函数回归。
2. **纯音频在内容模式下停在设计器默认大窗口**：内容尺寸为空时原逻辑直接返回，但启动阶段又跳过了初始画面尺寸；现在媒体打开事件在“无内容且当前不是视频”时补 `应用初始画面尺寸`，纯音频恢复 854×480 预设（@150% 为 1281×720）。

**尚未完成的 GUI 项**（环境限制，不是代码通过）：

- 手动 `R` / `Shift+R` 旋转与 `F11` 全屏进出：无法取得应用键盘焦点，未做真实按键验证；自动旋转元数据路径已实测通过，手动旋转走同一 `更新内容旋转` 回调。
- 100% / 125% / 200% DPI：本轮只覆盖 150%；需要改显示缩放后再测。
- 多显示器：当前仅单屏；需要第二块屏验证 `Screen.FromControl` 切换与副屏最大化。
- 设置页复选框点击、尺寸菜单“原始视频”手动覆盖：未做点击验证；设置文件读取与关闭模式回归已通过。
- 本轮没有截图/鼠标操作授权，所有断言来自窗口与子控件物理尺寸，不是视觉截图比对。

## 8. 验收标准

1. 模式关闭时，旧“初始画面尺寸”行为逐位不变；老设置文件不迁移、不误读。**（已实测：模式关闭 1280×720 视频内容区 1281×720，等于 854×480 预设 @150%）**
2. 模式开启、内容放得下时，`画面控件.ClientSize` 的设备像素 = 旋转后内容宽高；截图逐像素比对无缩放。**（已实测 1280/1920/2560/640/1080×1920/图片/90° 旋转，物理像素严格相等）**
3. 内容≥工作区或目标窗口≥工作区时，`WindowState=Maximized`，窗口边界完整落在 `WorkingArea` 内。**（已实测 3840×2160 图片 `IsZoomed=True`；纯函数回归覆盖）**
4. DPI 变化后内容区设备像素不随 DPI 放大；窗口重新居中/最大化正确。**（仅实测 150%；100/125/200% 待补）**
5. 图片启动、全屏、手动尺寸、纯音频、多显示器五条边界均不崩溃、不抢状态。**（图片/纯音频已实测；全屏、手动尺寸、多显示器受环境限制待补）**
6. 旧内核（无 `SetFitLimitToNative` 导出）不抛异常；仅记录能力缺失。**（代码与 42 条 PR57 回归覆盖，未在旧内核二进制上单独跑 GUI）**
7. 新增回归套件与既有两套测试全绿，所有工程 Debug/Release 0 错误。**（16/16、42/42、29/29，Debug/Release 全解决方案均 0 错误）**

## 9. 风险与边界

| 风险 | 影响 | 处理 |
|---|---|---|
| 内容=显示器时普通窗口 chrome 占像素 | 无法严格 1:1 | 用户已确认直接最大化，**不再实现**隐藏 chrome 的沉浸式方案 |
| 最大化后 chrome 仍在 | 内容被拟合缩小 | 已接受，不算缺陷；设置页说明 |
| 默认 `MinimumSize 875×500` | 小内容面板大于内容 | 内容模式临时放宽到目标，退出恢复；640×360 已实测 |
| `SetFitLimitToNative` 旧内核缺导出 | EntryPointNotFoundException | 已改动态可选导出；不支持则跳过 |
| 媒体打开即改窗口 | 首帧黑闪/交换链重绑 | 媒体事件末尾应用；主动 `重绑输出窗口`；避免逐帧 |
| 图片启动先开图后 Attach | 非客户区量错 | `界面已就绪` 二次应用 |
| DPI 单位混用 | 1:1 变成 1.25×/1.5× | 新路径只用设备像素；不调用 `按DPI缩放`；DPI 变化重放 |
| 多显示器 WorkingArea | 最大化到错误屏幕 | `Screen.FromControl`；启动未显示时主屏兜底，显示后重算 |
| 全屏被自动最大化打断 | 全屏状态错乱 | `全屏状态` 优先；进入全屏关闭封顶，退出后重放 |
| 手动尺寸被自动覆盖 | 用户选择被抢 | `手动覆盖` 到下一媒体 |
| 纯音频无内容 | 停在设计器默认窗口 | 媒体事件补默认初始尺寸 |
| SAR/DAR 非方形像素 | 目标宽高与渲染拉伸不一致 | 按 coded raster；不承诺变形源 1:1 |
| 360° 投影 | 平面 1:1 无意义 | 当前基线不跳过；后续可加投影判断 |
| 视频流切换 | 窗口不跟随 | 首版不自动；用户手动“原始视频” |
| 旋转 | 窗口不跟随 | 已接 `视图旋转控制器` 回调；90° 元数据已实测 |
