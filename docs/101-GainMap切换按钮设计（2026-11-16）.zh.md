## 1. 原生侧契约（C++）

### 1.1 状态与接口

```cpp
// PlayerSession.h
bool gainMapEnabled_ = true;                 // 默认启用；每张图片打开时重置为 true
FFFResult SetGainMapEnabled(bool enabled);   // 只切开关 + 必要时重绘当前静图
```

```cpp
// PlayerApi.cpp（追加导出，不 bump PlayerApiVersion / SnapshotVersion）
FFFResult FFF3FP_SetGainMapEnabled(const FFF3FPHandle player, const uint32_t enabled) noexcept;
```

导出采用与 `FFF3FP_SetVideoAutoHdr` 相同的"追加"模式：老宿主解析不到该符号时降级为"无此能力"，不得抛 `EntryPointNotFoundException`。

**返回值语义**：成功 `Success`；没有 handle → `InvalidArgument`；当前不是静态图片、或没有可用的 `baseRgba` / 不是 `applyOk` → `InvalidState` 或 `NotSupported`（由实现决定并写注释）。**失败时开关不得半边生效**（要么整体拒绝，要么成功切换并重绘）。

### 1.2 帧选择点

唯一替换点 `PlayerSession.cpp` 的 `handleFrame` lambda（现 `:6583` 起）：

```
选哪个缓冲：
  enabled && applyOk && !appliedRgba.empty()      -> appliedRgba（现行行为）
  !enabled && !baseRgba.empty()                   -> baseRgba（原始底图）
  !enabled && baseRgba.empty()                    -> 回退 appliedRgba，并记一次 note（不得崩、不得黑屏）
两者都不可用 -> 保持 decoded（原样）
```

打包成 `AVFrame` 的属性与现行一致：`AV_PIX_FMT_RGBAF32LE`、`AVCOL_PRI_BT709`、`AVCOL_TRC_LINEAR`、`AVCOL_SPC_RGB`、`AVCOL_RANGE_JPEG`，尺寸取 `outW/outH`，`pts`/`best_effort_timestamp` 沿用被替换帧。

**禁止**：切换时重新 `GainMapProbe::Probe`、重新解码文件、重新打开会话。

### 1.3 切换后的重绘

`SetGainMapEnabled` 成功后，若当前是静态图片且选中缓冲可用，必须把选中缓冲**重新打包成 AVFrame 并通过现有呈现路径刷新当前画面**（`PresentVideoFrame` 或会话现有的单帧刷新入口）。要求：

- 不改变帧序号 / 呈现计数器语义（不得让播放器认为"来了一帧新的视频帧"）；
- 不打断播放/暂停状态（切完仍是原来的暂停/播放态）；
- 不产生重复队列（不得既入队又直呈同一帧）；
- 只重绘一次。

### 1.4 `RebuildMediaInfo` 的 `gainmap` JSON

在现有键（`present` / `form` / `verdict` / `reason` / `headroomLinear` / `baseHdrHeadroomLog2` / `altHdrHeadroomLog2`）基础上**补**：

| 键 | 类型 | 语义 |
|---|---|---|
| `applyOk` | bool | 是否真的施加成功（不是"识别到"） |
| `baseAvailable` | bool | `baseRgba` 是否可用（决定能否切回原始） |
| `outW` / `outH` | int | 施加后画面尺寸 |
| `targetHeadroomLog2` | double | 探针/会话的目标 headroom（缺省 4.9） |
| `applyWeight` | double | 实际权重 `w` |

（`baseHdrHeadroomLog2`/`altHdrHeadroomLog2`/`headroomLinear` 已在上一轮就有，保持；旧 `headroom` 若曾存在则保留但**不作为唯一判据**。）

### 1.5 会话生命周期

- `DoOpen` 时：`gainMapEnabled_ = true`（每张图片默认启用）；
- 换图 / 关闭 / 重置会话（现 `gainmapInfo_ = GainMapProbeResult{}` 的位置 `:9202`）：一并复位 `gainMapEnabled_ = true`；
- 视频文件：`gainMapEnabled_` 无意义，`SetGainMapEnabled` 返回失败，UI 不显示按钮。

## 2. 宿主侧契约（VB.NET）

### 2.1 控件命名与插入位置

| 项 | 名称 |
|---|---|
| 按钮 | `MB_GainMap切换`（`LakeUI.ModernButton`） |
| 5px 占位 | `JEC_GainMap切换前面的空白占位`（`LakeUI.JustEmptyControl`） |

`Panel4` 是 `Dock.Left` **逆序**布局（先 `Add` 的在更右侧）。现有顺序（自右向左的添加序列）：… `MB_当前视频编码显示` → `JEC_当前视频编码显示前面的空白占位` → `MB_HDR模式` → `JEC_HDR选项前面的空白占位` → `MB_软件解码或硬件解码`。

**插入点**：在 `Panel4.Controls.Add(MB_HDR模式)` 之前，按
`Add(MB_GainMap切换)` → `Add(JEC_GainMap切换前面的空白占位)` → `Add(MB_HDR模式)` 的顺序插入。
结果左→右为：`MB_HDR模式` → 5px 占位 → `MB_GainMap切换` → 5px 占位（原视频编码占位）。即 **GainMap 紧邻 HDR 右侧**，不挤压任何现有按钮。

### 2.2 可见性

```
可见 = 快照.是静态图片 AndAlso 信息.GainMap 可用
可用 = GainMap.applyOk AndAlso GainMap.baseAvailable
```

- **不得**用 `是HDR源` 判可见（GainMap 也可能出现在 SDR 源上）；
- 视频、普通无增益图图片：`设置配对可见(MB_GainMap切换, JEC_GainMap切换前面的空白占位, False)`；
- `decoded_not_applied` / `fail_closed_*`：不显示按钮（若实现选择"显示但置灰"，必须在交付说明里写清并给出可见条件，不能把"识别到"写成"已施加"）。

### 2.3 文本与 Tooltip

- 通过现有 `设置自适应文本` 机制设置文本：原生开关为**启用** → `GainMap`；**关闭** → `原始`；
- Tooltip：`点击在 GainMap 与原始底图之间切换`；
- 文本与颜色/状态**以原生实际开关为准**：调用 setter 后以返回码 + 重新读取的实际状态刷新；setter 失败要恢复 UI 到切换前状态并给出操作信息（不得只翻转本地布尔值）。

## 4. 验收矩阵

1. `MSBuild FFF.Native.vcxproj /p:Configuration=Release /p:Platform=x64` → 0 错误；`dotnet build FFF.Player\FFF.Player.vbproj -c Release` → 0 警告 0 错误。
2. 导出数：基线 133 → 期望 **134**；与基线名单做差：只允许新增 `FFF3FP_SetGainMapEnabled` 一个，删除应为 0。
3. 两态像素证据（`imazen/heic` 的 `apple_hdr_sample_imazen.heic` 与 `seine_sdr_gainmap_srgb.avif` 各一次）：
   - 开图默认 GainMap（`FFF3FP_CopyFrame` 取到的 maxLinear ≈ 7.37 / 2.45）；
   - 调 `FFF3FP_SetGainMapEnabled(0)` → 同一文件 `CopyFrame` 取到的 maxLinear ≈ 1.0（原始底图）；
   - 再调 `(1)` → 回到 ≈ 7.37 / 2.45；
   - 两态**必须逐像素不同**，不是只改文字（对比统计：均值/最大值/差异像素占比）。
4. UI 可见性：普通 SDR 图（`plain-jpeg.jpg`）、视频（任一 mp4/avi）→ 按钮不可见；`skia-…-adobe-gcontainer.jpg`（`fail_closed_malformed`）与 `seine_hdr_gainmap_srgb.avif`（`decoded_not_applied`）→ 不可见或明确置灰。
5. 失败回退：在没有 GainMap 的文件上调 `FFF3FP_SetGainMapEnabled` → 返回失败码（非 `Success`），宿主不改变文本、给出提示。
6. 不做重复探测的旁证：切换前后会话的 `gainmap.verdict` 不变；日志中无第二次 probe 记录（若实现无日志，用"We open 时 probe 一次"的代码路径自证 + 说明）。
