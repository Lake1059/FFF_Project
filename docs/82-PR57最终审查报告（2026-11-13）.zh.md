- `Form设置_AI字幕.vb` 是宿主设置页；`AI字幕菜单.vb` 是宿主标题栏菜单；字幕源列表里也有 AI 项。

- 因此 F-01 不再是发布阻断项。需要修正的是对外表述：不能同时说“所有信息都由模块注入”，应写“AI 是宿主基础能力；色彩变换模块只注入其自有 HDR/合成文本”。

### F-02（P2，窗口边界）手动尺寸没有恢复临时放宽的 MinimumSize

**事实**：

- 内容模式会把 `MinimumSize` 临时放宽到能容纳小内容（如 640×360）：`播放器窗口布局控制器.vb:227-230`。
- `标记手动尺寸` 只做 `手动覆盖=True`、`设置封顶(False)`，**没有恢复 `默认最小尺寸`**：同文件 `:150-156`。
- `应用画面尺寸` 仍用 `窗体.MinimumSize` 做 `Math.Clamp`：同文件 `:177-178`。
- 因此：内容模式先播放小视频 → 再手动选一个比临时最小尺寸更小的目标 → 窗口会被 `MinimumSize` 夹住，内容区不再是用户选的目标尺寸。
- `应用内容原始尺寸` 的空内容分支（纯音频/无视频）只清空 `最后内容...` 并返回，**没有 `设置封顶(False)`、没有恢复 MinimumSize**：同文件 `:86-90`。从小视频切纯音频时，可能继承一个偏小的最小尺寸。

**判断**：

- 不是主路径自动 1:1 的缺陷；双屏矩阵测的是媒体打开/旋转/全屏，不是“手动选择小于当前 MinimumSize 的目标”。
- 属于手动尺寸/纯音频切换的边缘回归，标 P2；如果产品要求手动尺寸也必须严格 1:1，则应升到 P1。

**建议**：

- `标记手动尺寸` 内恢复 `窗体.MinimumSize = 默认最小尺寸`（或按手动目标重新计算一个合理下限）。
- 空内容分支恢复 `设置封顶(False)` 与默认 `MinimumSize`。
- 加两条回归：小内容→手动更小尺寸；小内容→纯音频→初始尺寸。

### F-03（P2，P2-A 风险）影子解码没有长时/弱机 CPU 证据

**事实**：

- `PlayerSession.cpp:2909-2964` 的 `FeedAsrShadow` 复用 `audioDecoder_`，在 `HandlePassthroughPacket` 的 `EnqueueBitstream` 之后执行（`:6241-6243`）。
- 连续 200 次解码错误后 `asrShadowDisabled_=true`；任何成功帧清零；seek 时清零并重新允许（`:8297-8301`）。
- 设计上只增加“AI 开启且直通生效”时的解码 CPU；没有新增队列/线程。

**判断**：

- 代码路径合理，未确认越界/泄漏；但 TrueHD 7.1 在弱机上是否 underrun、200 AU 阈值是否合适、seek 多次往返是否稳定，**没有实测**。
- `FeedAsrShadow` 与渲染入队同线程；如果解码时间超过 burst bank 吸收能力，直通音频先受影响，这是设计已知风险。

**建议**：

- 至少补一次 TrueHD/DTS-HD 直通 + AI 开/关/seek/回退的长时实测，记录 `asrShadowDisabled`、`blocksDropped`、underrun、单核 CPU。
- 若弱机 underrun，按文档 §5.4 的退化顺序处理（半帧率→独立线程+队列→提示二选一），不要静默降级。

### F-04（P2，供应链）AI 包是“哈希信任清单”，不是签名机制

**事实**：

- `Ai字幕包下载器.vb` 使用固定公共 URL + SHA256 钉死；`.part` 续传；`ZipFile.ExtractToDirectory` 解压；下载目录白名单；`.3fp-package.json` 归属哨兵；删除只认哨兵。
- 这套对“误删用户目录”和“下载中断”的防护是有效的；P1-2 的回归套件也覆盖了哨兵/白名单。
- 但 SHA256 常量在应用内是**信任清单**，不是独立签名；如果清单/更新通道被篡改，或用户手动选择的包本身含恶意 worker，应用无法证明来源。ZIP 解压安全边界依赖哈希命中，不是独立的路径校验/签名验证。

**判断**：

- 作为当前“官方固定源”方案可接受；不能宣传为“签名校验”。
- 用户手动放置的第三方包可以执行 Python worker，这是扩展机制的固有风险，应在 UI 明示“只使用可信包”。

**建议**：

- 官方包增加 detached signature 或至少签名的 manifest；解压前校验 ZIP entry 路径，拒绝绝对路径/`..`；在临时目录解压后再原子移动。
- 文档把“SHA256 固定清单”与“代码签名”区分开。
