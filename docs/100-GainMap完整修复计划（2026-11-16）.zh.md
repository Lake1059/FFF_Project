## 2. 判据、公式与单位（本轮唯一口径，实现与验收共用）

### 2.1 HDR base 判据（P0-1）

设 `hB` = `baseHdrHeadroom`，`hA` = `alternateHdrHeadroom`，**单位 log2 stops**（线性倍率 = `2^`）。

```
若 hB > hA            -> base 已是 HDR：verdict=decoded_not_applied，只显示 base，不施加；
                           reason 写 "base HDR (baseHdrHeadroom=.. > alternateHdrHeadroom=..)"
若 hB <= hA           -> 按目标 headroom 计算权重 w：
                          w = clamp((target - hB) / (hA - hB), 0.0, 1.0)   // hA==hB 时规定 w=1.0 并记 note
                          target = 播放器/CLI 传入的目标 headroom（stops）
                          探针新增 --target-headroom <stops>，缺省常量 kDefaultTargetHeadroomLog2 = 4.9
```

- `flags` 字节只允许用于两处：`0x80` = `is_multichannel`（通道数 3/1）、`0x40` = `use_base_colour_space`（色彩空间选择）。
  **不得再出现任何"HDR base"位判断**；`0x3F` 保留位非零 → `fail_closed_unsupported`（reason 说明保留位）。
- 两条路径（tmap/HEIC 与 JPEG APP2）必须走同一个判定函数，判据只来自 `hB/hA`。
- 无 headroom 元数据的件（如 `synth_heic_grid_aux_noxmp.heic`）：维持 `fail_closed_unsupported`。

### 2.2 施加数学（P0-2）

单通道/三通道 ISO 族：

```
g        = pow(gainNormalized, 1/gamma)                 // gamma>0 已校验
log2Gain = gainMin[c] + (gainMax[c] - gainMin[c]) * g   // log2 stops，带符号
log2Gain = min(log2Gain, altHdrHeadroomLog2)            // headroom 上界钳制，见下
mult     = pow(2, w * log2Gain)                         // w 见 2.1；w==0 -> mult=1
out      = (base + w*offSdr[c]) * mult - w*offHdr[c]    // 结果 >=0 钳制；w==0 时恒等 base
```

**headroom 上界钳制（本轮新增，证据驱动）**：增益图层能产生的 boost 不得超过该件声明的 alternate headroom `2^altHdrHeadroomLog2`。依据是实测反例 `gainmap-regress\pos_sdrbase_ubcs1.avif`——`hB=0/hA=1.3` 但 `gainMax=11`，元数据自相不一致，旧探针据此输出 `maxLinear=2048`，与该件自己声明的 1.3 stops 差 8.6 stops。复审报告、验收方、实现方三方独立结论都要求它落在 `2^1.3*1.05≈2.58` 内。钳制只压上界、保留暗部加深；对自洽语料（`seine_sdr` 的 `gainMax=1.277 < hA=1.3`、vendor128 的 `gainMax=hA`）**恒不触发**。触发时必须在 `notes` 记 `gain clamped to alternate headroom (gainMax=.. > hA=..)`，让钳制可见、不静默。

- `gainMapMax` **绝不直接当倍率**；必须经 `gamma` 反变换 + `w` 加权。
- Apple 0-base 族（`isAppleFamily`）：`out = base * (1 + (2^(w*headroomLog2) - 1) * gApple)`，`gApple` 由增益图层线性化得到。
- vendor128（`isVendor128`，128 基）：`gainMin=-h, gainMax=+h, gamma=1`，同样吃 `w`。
- JPEG：`hdrgm:HDRCapacityMin/Max` **必须**进 `hB/hA`（见 2.3 命名），不得 `(void)` 丢弃。

### 2.3 单位与命名（P1-3，硬约定）

| 语义 | 字段名 | 类型/单位 |
|---|---|---|
| base 侧 headroom | `baseHdrHeadroomLog2` | double，log2 stops |
| alternate 侧 headroom | `altHdrHeadroomLog2` | double，log2 stops |
| 线性倍率（仅展示用） | `headroomLinear` | double，= `2^max(hB,hA)` 或家族语义下的倍率 |
| 目标 headroom | `targetHeadroomLog2` | double，log2 stops，缺省 4.9 |
| 实际权重 | `applyWeight` | double，[0,1] |
| 探针结果里的旧字段 `headroom` | **删除** | 不再输出裸 `headroom` |

- JSON 键名：`meta.baseHdrHeadroomLog2` / `meta.altHdrHeadroomLog2` / `meta.headroomLinear` / `meta.targetHeadroomLog2` / `meta.applyWeight`。任何保留的兼容键必须在 JSON 里带 `_log2`/`_linear` 后缀。
- `GainMapJpeg`（`JpegGainMapHit`）里原来的 `headroom` → `headroomLog2`（Apple v1/v2/v3 与 Ultra HDR 均按 stops 填），另加 `baseHdrHeadroomLog2`、`altHdrHeadroomLog2`、`hdrCapacityPresent`、`app2Flags`、`app2ReservedFlagsNonZero`。
- `GainMapProbe` 内部只搬 `*Log2`，转线性只在填 `headroomLinear` 时做一次。

### 2.4 校验（P1-1/P1-2，全部 fail-closed）

1. `gainMin[c] <= gainMax[c]`，任一通道违反 → `fail_closed_malformed`（reason 带通道与数值）
2. `gamma[c] > 0`
3. 所有有理数分母 `> 0`（headroom 与每通道各字段）
4. `flags & 0x3F != 0` → `fail_closed_unsupported`（保留位）
5. tmap v0 定长之后仍有剩余字节 → `fail_closed_unsupported`（保持现状）

### 2.5 数值上限自证（验收断言，P0-2 配套）

```
maxLinear <= 2^(w * max_c(gainMax[c])) * 1.05            // ISO 族
maxLinear <= 2^(w * headroomLog2) * 1.05                 // Apple 族
且 hB > hA 的件不得出现 verdict=applied
```

**B. 新增反例（必须新建，堵 flags 反例）**
1. `1ch HDR-base tmap`：`flags=0x00`、1 通道、`hB=3.0/hA=0` → 必须 `decoded_not_applied`（堵旧 `&0x80` 门槛漏判）

4. 保留位反例：`flags=0xC8` → `fail_closed_unsupported`
5. `gainMin>gainMax`、`gamma=0`、分母 0 → `fail_closed_malformed`

**C. 确定性**：抽查 ≥5 件（含 1 件 JPEG、1 件 grid、1 件 Apple HEIC）各 20 次，`appliedRgba` 逐字节哈希一致。
